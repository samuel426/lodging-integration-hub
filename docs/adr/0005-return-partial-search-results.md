# ADR 0005: 부분 검색 결과 반환

- 상태: Accepted - POL-003 C안
- 제안일: 2026-09-03

부분 성공 원칙을 유지하면서 정상 빈 결과와 데이터 불능을 구분하는 C안을 2026-09-04 승인했습니다.

2026-09-03 초안은 해석 가능한 batch가 있으면 전부 거절되어도 200을 제안했습니다. 데이터 불능을 정상 무결과로 숨길 수 있어 채택하지 않았습니다. 아래는 이를 대체하는 승인된 결정입니다.

## 배경

다수 Supplier와 batch를 조회하면 일부 호출만 실패하거나 한 응답 안의 일부 offer만 잘못될 수 있습니다. 하나의 실패 때문에 모든 정상 결과를 버리면 가용성이 불필요하게 낮아집니다. 반대로 실패를 숨기면 소비자가 결과의 완전성을 오인합니다.

## 결정

유효한 offer(업무 필터링 전), 검증된 명시적 빈 availability batch, 정상 빈 catalog 중 하나라도 있으면 HTTP 200을 반환합니다. 실패 batch, 개별 offer 거절, 미준비 catalog가 있으면 `meta.partial=true`와 각각의 요약을 제공합니다. 전부 품절이어도 상품 검증을 통과했다면 정상 관측입니다.

유효한 관측이 전혀 없으면 알려진 연동 설정·요청 오류는 500, catalog mapping 불일치는 503, 외부 데이터 계약 위반은 502, 나머지 전체 외부 이용 불가는 503으로 처리합니다. 예상하지 못한 내부 결함은 정상 상품 존재 여부와 무관하게 500이며 Supplier 장애로 흡수하지 않습니다. 모든 catalog가 미준비이면 조회 전에 503을 반환합니다. 정확한 순서와 오류 코드는 [응답 정책](../search-response-policy.md#5-최종-응답의-판정-순서)에 정의합니다.

개별 offer의 오류는 해당 offer만 제외합니다. 배치 본문 자체를 해석할 수 없거나 호출이 실패한 경우에는 배치 전체를 실패로 처리합니다.

## 결과

- 독립적인 성공 결과를 최대한 보존합니다.
- 소비자는 `meta`를 통해 불완전성을 확인할 수 있습니다.
- 실패를 값으로 수집하는 orchestration과 메트릭이 필요합니다.
- 반환 건수와 관측 성공 수를 별도로 집계하고 batch 실패와 개별 거절을 이중 집계하지 않습니다.
- 완료 순서와 무관한 판정을 S01~S16으로 검증합니다. 승인 시점에는 미구현입니다.
- 결과 순서는 병렬 완료 순서와 무관하게 계약에서 보장하지 않습니다.

## 검토한 대안

- 하나라도 실패하면 전체 503: 단순하지만 장애 격리가 되지 않습니다.
- 실패를 숨기고 항상 200: 결과가 완전한지 알 수 없습니다.
- 개별 offer 오류로 batch 전체 실패: 다른 유효한 상품까지 제거합니다.
