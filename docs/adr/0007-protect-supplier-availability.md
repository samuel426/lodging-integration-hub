# ADR 0007: 반복 장애 공급사의 실시간 조회 보호

상태: Accepted — 2026-09-07, POL-004

## 문제와 판단 기준

타임아웃은 한 번의 대기를 제한하지만, 장애가 계속되는 동안 새로운 검색도 같은 대기를 반복합니다. 검색 가능한 다른 공급사 결과는 유지하면서 반복 대기와 불필요한 요청을 줄이는 것을 우선합니다. 부분 결과를 전체 결과처럼 보이게 하지 않아야 합니다.

## 선택

availability batch 앞에 공급사별 Circuit Breaker를 둡니다. 연결 오류, 타임아웃, 서버 오류, 호출 한도 초과를 반복 장애 근거로 사용합니다. 인증·요청 설정 오류와 잘못된 상품 데이터는 일시적인 가용성 장애와 구분하고 기존 오류 정책으로 드러냅니다.

차단 중 신규 HTTP 호출을 보내지 않고 공통 실패 결과에 `CIRCUIT_OPEN`을 기록합니다. 정상 공급사의 유효 관측이 있으면 부분 성공을 반환합니다. 차단 시간이 지난 뒤 제한된 호출로 복구를 확인합니다. 상태는 인스턴스 내 공급사별로 공유하며 catalog에는 적용하지 않습니다.

## 비교한 대안

| 대안 | 이점 | 채택하지 않은 이유 |
|---|---|---|
| 타임아웃만 유지 | 상태 없는 단순한 처리, 복구 직후 바로 조회 | 반복 장애에도 매 요청이 같은 대기 비용을 지불 |
| 자동 재시도 추가 | 짧은 일시 장애에서 같은 요청 안에 복구 가능 | 전체 검색 지연과 장애 공급사 부하 증가, 시간 예산·한도 정책 필요 |
| 이전 결과 cache | 공급사 조회 없이 빠르게 응답 | 가격·재고 최신성 손실을 허용하는 별도 서비스 정책 필요 |

## 감수하는 손실

- 실제 공급사가 복구되어도 차단 대기와 복구 확인이 끝나기 전까지 결과를 누락할 수 있습니다.
- 최근 batch 수로 판단하므로 숙소가 많은 검색은 관측 구간을 빠르게 채웁니다.
- 공급사별 공유 상태로 같은 시점의 검색들이 영향을 주고받으며, 여러 인스턴스 사이의 상태는 공유하지 않습니다.
- 전체 검색 deadline이나 전역 동시 호출 상한을 제공하지 않습니다.
- 실패 enum을 닫힌 목록으로 처리하는 소비자는 추가된 category를 수용해야 합니다.

## 구체화와 검증

Resilience4j 2.4.0의 core·Reactor·Micrometer 모듈을 사용해 기존 publisher 경계에 적용합니다. 결과값으로 반환되는 외부 실패는 result predicate로 판단합니다. 예외만 집계하는 기본 동작을 그대로 적용하지 않습니다.

기본 설정은 최근/최소 10회, 실패율 50%, 차단 10초, 복구 확인 2회와 최대 대기 5초입니다. 운영 실측 전의 초기값이며 변경 근거는 공급사별 실패율과 복구 지표로 확보해야 합니다. 단위 테스트와 실제 HTTP 요청 수·복구 테스트, 로컬 실행 JAR smoke로 확인합니다. 상세 내용은 [설계와 검증](../circuit-breaker.md)에 있습니다.
